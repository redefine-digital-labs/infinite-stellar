# Infinite Stellar Durable Project Memory

This file contains stable facts that should survive individual implementation phases. Current work belongs in `CURRENT.md`; completed detail belongs in the linked handoff, code, tests, specifications, and Git history.

## Product invariants

- The owner reconfirmed on September 5: preserve and combine Dark Forest's mature core gameplay, visual hierarchy, controls and entry flow. Concentrate product innovation on Soul integration and season operations, not invented replacements for DF foundations or extra onboarding ceremony. Soul/Seat authorization and production safety gates still apply.
- Infinite Stellar is a Sui-native, zero-knowledge, fully onchain seasonal strategy game in pre-production. It has an experimental P0 Move foundation, a sealed Sui testnet interface canary, and a runnable local player vertical slice, but no playable ranked onchain release.
- An address authorizes; a Soul is the persistent actor; Animacraft supplies accepted visual material; a Commander Projection freezes the seasonal Soul/visual/role/Seat binding; a fixed Season Seat controls a temporary Civilization and owns Planets through `owner_seat_id`.
- One controller address may create at most one ranked Seat per league and season. Manifest-pinned registry parents and typed-key/shard vectors deterministically derive the Season Seat itself as the logical `ControllerLeagueSeasonSlot` and direct lookup. This is address-level fairness, not human-level Sybil resistance.
- A bounded enrollment-only capacity object atomically enforces manifest `max_ranked_seats`; it is not an ordinary-play global write.
- Atomic enrollment creates the Seat/binding/state set but no Planet. `CivilizationState` begins `AwaitingHome`; one later finalized `claim_home` creates the Seat-owned Founding Planet and changes it to `Active`. Pre-home Seats cannot move, score, colonize, or recover.
- The five-minute activation metric begins at chain-derived `HomeSearchAvailableAt`; `HomeClaimAvailableAt` separately records when submission is legal. A nonzero Clock-time observation delay rejects immediate claims but does not claim checkpoint separation. Public-seed local work remains possible during a claim pause, so pauses are never subtracted to make latency look better.
- Permissionless capped availability ticks credit the minimum home-claim window. At close, global `home_window_resolution` becomes `ClosedAvailable` or `CancelledUnavailable` before any Seat may act or finalize further; a delayed opening, pause, or unevidenced chain/ticker gap that leaves insufficient credit reaches global `HomeWindowUnavailable` cancellation/refund rather than player-caused missed activation.
- The official client resolves an existing fixed-controller Seat before current Soul ownership. Its encrypted map vault is Seat/controller-scoped and never follows Soul transfer.
- Civilizations, planets, energy, fleets, map advantage, score, and ranked power reset. Soul-linked history and expression may persist without creating ranked advantage.
- Soulidity is the canonical identity/ownership layer. Infinite Stellar validates the live Soul owner and ownership epoch but does not take Soul custody.
- The canonical Soulidity mainnet v1 ABI is compile-time pinned in `soul_adapter` at source commit `a3a4a835e0298c3a4a0aba80943a05443770a9ef`, callable package `0x60bf39455f90e2af94381f2434d2c013c4e38a12fd16873ac296a26660f92ecd`, and original/type-origin package `0xa43cc9a94caa904a97316d97c08804369ee8fbe3335d2ddae154022d7d6e5d5d`. Core modules still accept only a package-internal, non-storable verified binding. Enrollment reads State/Soul IDs, current owner, ownership epoch, and listing state from canonical `&SoulState` in the same transaction; it is implemented and SDK-buildable but undeployed.
- The typed game SDK and English React client implement the activation journey with demo Soul/Seat fixtures, real local Round-5 home mining, controller-scoped persistence, and existing-Seat-first resume. Local entry searches and verifies an actual home after Soul selection without simulated approval/finality ceremony. New games have no precomputed neighbor geography or forced facility types. Completed search work and active games survive return/reload; returning home preserves the save. Demo screens cannot produce a Sui or Soulidity write or restore ranked authority from local storage. The SDK constructs canonical enrollment plus proof-bound home/move/move-new transactions, simulates them with checks enabled, rejects resolved execution failures, waits for indexed finality, reconciles exact BCS events/effects, discovers canonical shared Soulidity State through events plus live BCS, derives the controller Seat from the exact Move typed key, and BCS-validates its Projection/Civilization/Score bundle. The React ranked route now uses those identity/Seat reads and connects the guarded enrollment lifecycle. Production-verifier readiness remains false and exact release-evidence pins are absent, so the signing action remains unreachable.
- Infinite Flow Engine may host a separate Soul-bound prologue or PvE Scene with independent history; it is neither the guest tutorial nor the asynchronous multiplayer universe authority.
- Private coordinates and map secrets remain local. Outcome-changing rules and settlement are authoritative on Sui.
- The web client supports continuous manifest-bound discovery with persisted completed chunks and namespace-bound authenticated portable map backups. Restored coordinates are verified locally; ownership/resources come only from fresh chain reads. Local-simulation commands share preview/dispatch logic, but their availability is not evidence of deployed ranked action adapters.
- Proof interface v1 binds a sixteen-field Sui Poseidon action tuple. `claim_home` and normal `move` retain four BN254 public signals; the action-specific `move_new` extension has five and additionally exposes proof-derived destination space Perlin. For `move` and `move_new`, `amount_u64` means maximum route distance; transferred energy and silver remain live-state arguments. Checked-in Circom 2.2.3 relations cover manifest-committed radius/rarity/MiMC/Perlin/home/distance geometry. Each Season binds exact claim/move/move-new `CircuitConfig` IDs plus config and verifying-key digests. Move recomputes public inputs, invokes Sui Groth16, creates internal witnesses only after verification, and consumes a source-Planet nonce on successful dispatch. `move_new` atomically claims the deterministic destination Planet, derives neutral stats from the verified location hash and Perlin, and dispatches the Voyage; any downstream abort rolls all mutations back. Development proofs exercise real home, move, and move-new state changes; sender mutation, expiry, config substitution, caller Perlin substitution, occupied-location races, and replay reject. Dark Forest location IDs remain fixed 32-byte big-endian for planet generation while Groth16 public scalars are separately little-endian. All current keys/artifacts remain development-only; no production-approved config constructor exists, so ranked writes stay fail-closed until reproducible builds, expanded review, setup ceremony, independent audit, and code-pinned production-key activation pass.
- The initial release has no fungible token, land sale, yield loop, or paid ranked power.
